# Issue #3：前端初步设计与交互说明

## 一、设计目标与范围

本次设计依据《产业出海智能服务系统》项目计划书 V1.0 与 GitHub issue #3，服务于项目报告中的界面展示和使用流程说明。原型聚焦泰国、印度尼西亚和越南，提供新能源汽车、跨境电商两个行业入口。界面借鉴 Kaggle 的白色底色、常驻左侧功能导航、圆角卡片、清晰标题层级及适量留白，使用蓝色表达探索入口，以黑色主按钮突出关键操作。品牌暂定“远航”，最终命名可由团队确认。

交付为可运行的 Vue 页面，而非单张效果图。首页、市场看板、合规筛查和 AI 智能问答共享页面框架。左侧导航支持折叠，当前功能以浅色底高亮。窄屏压缩侧栏为图标，并将卡片、图表和表单改为单列。按钮保留键盘焦点，输入框具备标签，动态文本使用 Vue 默认转义机制展示。

## 二、首页原型

首页承担系统定位说明与功能分流。顶部展示系统标识、当前位置和原型版本，显著提醒当前为演示模式。主视觉以“让下一站市场，成为有据可循的选择”为主题，配合代码绘制的地球图形，避免依赖第三方图片。用户可通过主按钮进入市场看板，也可点击三张国家卡片直接进入对应国家。

统计区域展示三个重点国家、两个关注行业、五个筛查维度和规划采用的 RAG 技术。这些数字表示原型覆盖范围，不表示已经采集的数据规模。下方分别提供行业入口和政策观察入口，政策条目只展示类别及待接入状态，不虚构税率、生效日期或政策出处。

## 三、地图与市场看板

地图看板采用东南亚位置示意图和可点击国家标记，展示本学期 MVP 的重点区域。当前图形不是精确国界地图，也不代表完整世界地图已经实现；后续可在地理数据授权与来源确认后替换为 ECharts GeoJSON 世界底图。点击国家或改变国家下拉框时，右侧国家概况和市场图表同步切换。概况包括国家、首都、货币与关注行业，市场规模和供需缺口保留待接入状态。

趋势图由 ECharts 渲染，支持悬停查看季度示例指数，并随容器宽度调整尺寸。指数为合成数据，页面明确说明其不表示真实市场规模。用户点击“筛查该市场”时，国家和行业条件带入筛查表单，减少重复输入。政策列表预留官方来源、生效日期与更新时间的位置。

## 四、合规筛查页面

筛查表单包含目标国家、所属行业、产品类别或名称、HS 编码及原产国。产品名称不能为空，HS 编码必须由六位、八位或十位数字组成；格式校验不等同于商品归类正确。用户提交无效内容时，Element Plus 在对应字段下展示提示；有效提交后，原型展示五项待核验清单，包括进口税收、产品认证、原产地规则、市场准入和标签环保要求。

当前结果是交互占位，不输出真实税率，也不把“待核验”解释为“无风险”。正式联调时应增加加载状态、请求失败重试、无匹配结果和政策版本失效提示。任何合规结论都应关联适用国家、产品范围、政策原文及日期，不能只显示一句总结。

## 五、AI 问答页面

问答页提供建议问题、文本输入区、提交按钮、回答区域及独立政策依据面板。建议问题只填入输入框，不自动提交；空白内容禁用发送，输入长度限制为两千字符。提交后展示用户原始问题和明确标记的演示回答。原型不调用真实模型，不伪造检索来源，依据面板保持“暂无已核验来源”。

正式接入 RAG 后，回答应附可定位的政策条文、官方来源、更新时间及引用关系。证据不足时明确告知无法确认，不生成看似精确的税率。报告生成属于计划书的后续业务闭环，本次 issue #3 优先完成四个指定界面，不声称已提供正式研判报告服务。

## 六、技术栈与接口交互

采用 Vue 3 Composition API 管理视图状态，Vite 提供开发服务与生产构建，Element Plus 提供表单、校验和表格，ECharts 提供数据图表，Axios 作为后端通信层。Lucide 提供一致的线性图标。页面不使用动态记忆项目的 Streamlit 技术栈，两套工程互不混用。

src/api.js 预留合规筛查和问答请求函数，默认基地址为 /api，也可通过 VITE_API_BASE_URL 配置。路径 /compliance/screen 与 /qa 仅为待协商接口，不能当作后端已实现的协议。当前页面仅使用本地演示逻辑。后续应先与 FastAPI 开发成员确定字段、错误码和来源结构，再接入 Axios，并在失败时保留输入、明确反馈。API 密钥应留在服务端，不放入浏览器环境变量。

## 七、运行与交付

在 05_Frontend 目录执行 npm install 和 npm run dev，使用终端显示的本地地址访问；npm run build 用于构建检查。正式数据接入前，应验证国家切换、行业带入、HS 边界输入、空问题、窄屏布局和来源缺失提示。原型截图与此说明可用于报告，不代表生产功能或政策准确率验收。
