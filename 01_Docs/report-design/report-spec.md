# 出海分析报告规格 v0.4

适用对象为中国企业负责出口业务与市场拓展的人员。目标是完成泰国或印尼市场进入前的第一轮核查。本文为组内评审初稿，字段用于对齐界面和生成结果，接口命名由团队确认。[取舍依据](competitor-analysis/differentiation.md) · [场景样例](report-example.md)

## 生成前的输入

先展示一页简短的业务信息表单。切换场景后只显示该场景的问题。生成前允许用户核对并修改答案，已经明确的信息不反复询问。

| 层级 | 生成前收集 | 缺少时怎样处理 |
| --- | --- | --- |
| **必须回答** | 出口地、目的国、具体商品及业务方式。整车场景确认是纯电还是其他动力、整车还是散件，以及乘用或其他用途。 | 这些条件决定报告查哪个市场、商品及准入路径。缺少时先提示填写，保留草稿。 |
| **按业务追问，可选「暂不清楚」** | 预计在哪个月进口？要估算协定优惠时，问车辆在哪里制造、供应商是否提供过说明这批货产地的文件。电商寄递估算税费时问申报金额及币种。 | 说明答案会影响哪项估算。可先生成报告，再向采购同事或供应商了解。 |
| **已有资料，选填** | 车型规格、同款商品以往的泰国进口申报编码、供应商提供的证明名称。 | 编码记录标明所属国家，与本单商品及当前税则交叉核对。首次出口可以直接跳过。 |

**系统负责查询与解释。** 从商品描述出发查目的国官方税则，给出匹配的商品类别、编码、依据与查询日期。有多个合理候选时，找出条目描述中真正区分它们的商品特征，用业务语言定向追问。缺官方记录时标出系统资料缺口，并附官方入口。泰国海关提供按商品描述或编码查询的方式。[泰国海关查询说明](https://ccc.customs.go.th/data_files/161221105447573888702.pdf)

再用匹配的商品、生产地和目的国查可能适用的协定、产品原产规则及证明要求，解释哪些条件已满足、哪些要向生产商核实。发货地、制造地、持有证书分别记录。系统承担初筛，企业及进口商在实际申报时核对商品和本批凭证。页面只向用户询问企业事实，税目和优惠资格作为分析结果呈现。

## 首屏应交付的判断

首页使用「建议做什么 → 为什么 → 优先核查什么」的顺序。给出有来源的判断和明确动作，例如「进入渠道和落地成本调研，先找泰国进口商做同价位对标和落地报价」。把少数会改变行动的问题集中到同一块，表内单项照常标明状态与来源。只有统计数据时可说明它支持的判断。市场证据也不足时，显示已能回答的问题及获取数据的路径，不凑数给推荐结论。

## 报告必须回答的业务问题

读者要决定是否为这个商品投入下一轮渠道、报价或准入准备。首屏写明建议推进到哪一步，以及最能改变决定的一项市场事实和一项政策或准入判断。正文按下面的业务问题展开。仅列查询入口、政策名称和“请咨询进口商”的报告不能通过内容验收。

1. **市场机会在哪里？** 给出与商品最接近的需求指标，再用一个同口径变化或竞争参照解释机会与约束。注明指标能支持的推论。例如中国制造车型份额高说明已有销售基础，也说明新进入者要跟现有车型竞争。
2. **哪项政策改变这笔业务的判断？** 从已检索到的规则中选出影响成本、销售条件或竞争格局的政策。写出主管机构、具体措施、适用对象、时间窗口、与用户条件的匹配结果，以及报价或渠道选择因此怎样改变。产业激励、协定优惠和强制义务分开呈现。资料仅足以说明历史规则时，明确它对当前测算的用途。没有可支持的相关政策时，说明查了什么、哪项判断仍缺依据。
3. **商品怎样进入市场？** 分别给出税目与优惠资格、产品标准与许可、进口或登记材料。每项交代谁办理、在哪个环节需要、现有文件能证明什么。只有目录记录时可以识别技术主题；要断言强制办理，还要有适用本商品的实施依据。
4. **企业现在能决定什么？** 给出可执行的建议，解释什么情况会改变建议。每个关键动作写明负责人角色、交付件和下一次决定，例如进口商交付按税费项目拆分的报价后，业务负责人决定是否推进试单。

首版就交付有依据的市场和政策分析。用户补充材料只用于细化依赖该材料的判断。企业自行提供业务事实，公开政策、政策日期和来源由系统检索。

## 页面结构和字段

| 区块 | 必需内容 | 展示规则 |
| --- | --- | --- |
| 查询范围与摘要 | 商品、路线、业务方式、分析日期、主要发现、重要缺项 | 首屏保留条件，每条重要发现引用正文条目。 |
| 市场观察 | 指标、数值或缺失状态、单位、期间、统计范围、来源 | 销量、进口额和当地生产分列。数据范围不同则不合算或直接比较。 |
| 行业与贸易政策 | 措施、适用主体、期限、条件、本单影响、原文定位 | 将政策事实与对本单的判断放在一起，区分直接资格和竞争环境影响。 |
| 关税与市场准入 | 事项、查询编码、匹配税目或候选、适用条件、有效时间、状态、依据 | 最惠国、优惠税率及资格分开。法规来源注明发布机构和条款或页码。 |
| 待核验与下一步 | 缺项或冲突、对判断的影响、补充材料、核查入口、关联条目 | 先列阻碍税目、资格或准入判断的事项。 |
| 来源与版本 | 来源编号、机构、标题、链接、定位、文件日期、有效期间、核验日期 | 来源随具体条目出现。参考链接与能支持当前结论的证据分别标注。保存每次生成所用的证据版本。 |

结论状态使用 **已核验、待核验、未取得资料、来源冲突、不适用**。已核验要求事实依据和适用条件均成立。报告可以保留已核验的部分；税目、期限或资格有关键缺项时，暂缓给出确定的税率或合规判定。缺失不得填成零。原文存在新旧版本时按适用日期及可确认的替代关系筛选；无法确认同一适用范围或版本关系时，列出差异及核查入口。

面向业务人员的准入条目应说清当前能报哪类价格、何时能承诺交付以及需要哪份业务材料。数据补录、候选排除日志和系统维护任务留给项目组。

## 生成与核验

1. 后端按场景查结构化数据与已核验资料，给每条证据分配引用编号。记录查询时点及资料版本。
2. 模型分节归纳，输出结论、引用编号、限制及待补条件。税率和统计值以结构化记录为准。
3. 程序校验引用是否存在、国家和日期是否匹配、数值及单位是否一致。字段缺失时该条转入待核验。测试阶段由成员核对关键结论是否被原文支持。
4. 前端按固定版式呈现。若本期交付导出，导出件应保留输入条件、数据口径、来源和缺失状态。

## 验收用例

| 用例 | 输入与依据 | 预期结果 |
| --- | --- | --- |
| RPT-01 税目不足 | 中国到泰国，新纯电乘用整车，用户未提供任何编码。 | 系统按商品描述检索，解释候选和排除依据。仅当额外商品特征能区分候选时追问。税则资料不足时说明数据缺口，继续展示市场判断。 |
| RPT-02 政策版本 | 泰国低值网购寄递场景，同时提供旧 FAQ 和 2026 年起调整的官方说明。 | 标明两条来源的日期和适用范围。新旧关系可确认时使用分析日期适用的记录；关系或适用条件不足时列明差异并给核查动作。 |
| RPT-03 指标口径 | 同时输入 IEA 泰国电动汽车销量与 GTH HS 870380 进口数据。 | 分列统计对象、时间与单位。分析可以指出变化，不能仅凭销量增长断言具体商品更适合进口。 |
| RPT-04 引用不可用 | 生成结果引用未入库编号，或引用材料来自另一国家。 | 对应结论不显示为已核验，也不影响其他可核验区块展示。 |
| RPT-05 生成前确认 | 未选整车或散件，或已选整车但原产资格暂不清楚。 | 前者提示先确认整车或散件，后者允许出报告并给出基础调研行动。 |
| RPT-06 补充后更新 | 原产资格未知，用户随后确认已取得某项证明。 | 新版记录用户新增信息，并说明接下来要按规则核对什么。仅凭用户自述不判定优惠合格。同口径市场数据可沿用。 |
| RPT-07 政策影响 | 2026 年拟进口泰国整车，资料同时包含 EV3.5 项目期限、2024 至 2025 年整车进口窗口及后续本地产车登记决定。 | 分别解释三个期限对应的事项。基准报价剔除已结束窗口的减免，单列本地生产政策对竞争者的影响。只有政策名称或查询链接不通过。 |
| RPT-08 证据层级 | 提供产品标准目录、官方 Form E 样式和用户业务描述。 | 能指出技术文件主题与原产证明路径。强制认证和优惠资格分别需要实施依据和交易材料。两者缺失均不妨碍输出已有依据的政策分析。 |

待评审项包括印尼和电商的实际样本覆盖、报告生成接口字段、资料复核负责人，以及开题的条数和字数指标如何与真实证据覆盖对齐。样例用于确认设计，不构成覆盖承诺。

生成前表单和报告判断规则为 v0.4 评审稿。交互式补问与报告版本更新仍是拟议功能，评审问题见[设计决策记录](design-decisions.md)。
